THEN: OPTIONAL OBSERVATIONS (not required before the push; anything unverified is marked UNVERIFIED).

- OBS-1 (IPC, `src/ipc/server/connection.rs:102`) — the new check bounds the WHOLE buffer by `max_line_length`, not a single line. With the shipped defaults (`max_line_length` == `max_connection_bytes` == 1 MiB) nothing legitimate is lost: a single frame can only trip it if the frame itself is over the limit, and any connection reading >1 MiB in total is dropped by the pre-existing `max_bytes` check anyway. But with a custom config where `max_line_length` < `max_connection_bytes`, a client that pipelines several VALID frames in one TCP segment (the server's own loop explicitly supports multiple lines per buffer) is now rejected with 413 even though every individual line is within the limit. Recommended follow-up (non-blocking): only reject when the buffer exceeds `max_line_length` AND no newline occurs within the first `max_line_length` bytes, e.g. `buf.len() > max_line_length && !buf[..min(len, max_line_length)].contains(&b'\n')`. UNVERIFIED: whether any shipped client pipelines multiple frames per connection.
- OBS-2 (XDP, `crates/ramshield-enforcement/src/xdp.rs`, the `plan.missing` insert loop) — behaviour change in map VALUES, not in the key set: previously every expected key was re-inserted with `PERMANENT` on every reconcile cycle, which also reset a TTL-scoped block to permanent; now a resident expected key keeps the value it already has, so a block inserted with a TTL can pass its expiry and stop being enforced even while it is still in the expected set. If the intended semantics are "TTL expiry wins" this is a fix; if the intended semantics are "reconcile re-asserts the block", it is an enforcement regression. The kernel KEY set is unchanged either way. UNVERIFIED: I did not read the BPF program's expiry check or the reconcile caller's expected-set source within the review budget.

That is inherent to an LPM trie (it is not a hash map) and is not a regression, but it remains the dominant per-cycle cost for large CIDR sets, unlike the blocklist path which is now insert-only-if-absent.
- OBS-4 (pre_aggs, `crates/ramshield-detection/src/pre_aggs.rs`) — the lock is now held for the WHOLE drain, including any flush triggered inside it. This trades latency for the strong bound; with a large `pre_aggs` the blocking window is now the walk itself.
